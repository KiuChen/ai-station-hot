# 多频道与艺术试点

一个网站入口与一套前端；每个频道复用相同 API、worker 和发布流程，并通过独立 PostgreSQL 数据库隔离内容、队列、缓存、事件与日报。当前频道为 AI（原入口）、艺术（`/art`）、美妆（`/beauty`）和 CS2（`/cs2`）。PostgreSQL 服务、品牌、管理员身份和登录会话共用。

## 配置与兼容

- `industry/channels.ts`：公开频道注册表与地址规则。
- `industry/profile.ts`：后端进程按 `INDUSTRY_PROFILE` 选择固定配置；没有跨请求的全局可变频道状态。
- `industry/taxonomy-ai.ts`：保留原有 AI 分类、标签与身份词典。
- `industry/profiles/art/`：独立艺术分类、主题、信源与完整提示词包。
- AI 保持现有网址、数据、提示词和门槛。原信源以及后台后续加入的阮一峰订阅均保存在原数据库。
- 艺术 API 与 worker 使用 `aihot_art`；身份验证通过 `AUTH_DATABASE_URL` 读取原管理员会话。前端只通过 HTTP 获取数据。
- 原有 publications.channel 继续表示 news/x；业务领域由独立频道进程与数据库确定。
- 收藏、已读和反馈草稿按频道保存，主题偏好共用；AI 原有浏览器存储键保持不变。

## 艺术试点

用户确认方向：绘画、插画、摄影与展览。六个类别：展览、作品、摄影、设计、创作教程、观点。信源：Colossal、Hyperallergic 与 Artforum News，180 分钟间隔，首次每个新信源最多导入 1 篇，摘要与原文链接，不开放全文展示或分发。

评分保留原有七种内部类型与五维加权结构，艺术配置提供新的领域解释。现有门槛仅用于试验评分与处理路径；艺术发布层禁止自动标为正式精选，页面明确提示门槛待样本校准。艺术首页优先展示官方看展预览，再提供近期动态；公开 selected 模式与精选 RSS 暂为空，试点列表不展示未校准的评分。

艺术的事件、热点、日报、周报和月报结构均独立；正式日报仍以精选资料为输入，因此精选未校准时不会伪造艺术刊物。艺术主题试读可读取普通公开动态。图片仅展示信源提供的素材，当前不自动评价图片美感或推断缺失的图像信息。

## 预算与提醒

首次设置在原模型次数预算内预留艺术试点：3 次/分钟、20 次/小时、50 次/天。原 10/60/500 的配置默认对应 AI 7/40/450 与艺术 3/20/50，相加保持原上限。艺术调用还会读取 AI 的历史滚动用量，切换当天也不能突破原预算。只有用户明确允许时，首次设置可通过 ART_PILOT_EXTRA_DAILY=50 将总每日上限提高到 550；本次用户另行授权测试期间提高到 800，测试后恢复 500；默认为 0。数据库首次准备之前先配置预算；用持久化标记防止重试或重建时重复扣减。若原预算不足，设置报错而不会自行扩大上限。

MiniMax 账户额度检查与飞书提醒仍由 AI worker 每 30 分钟执行，其他频道不重复发送机器人消息。内容推送与运营转发保持关闭。频道预算是调用次数上限，不是 Token Plan 或金额额度。

后台可以分别调整预算；调整后需要确保各频道额度之和仍满足账户预期。账户层仍需要在 MiniMax 平台核对积分、续费和套餐限制。

## 部署与恢复

`docker compose` 增加 art-setup、art-api、art-worker；web 的 `CHANNEL_API_BASE_ART` 指向内部 art-api，无额外公网端口。art-setup 创建数据库、执行同样的增量迁移、种子数据和首次预算准备。重复启动不覆盖后续后台修改的信源和预算。

上线前备份 AI 数据库、当前源码和镜像，并记录原预算。若回退：停 art 服务，恢复原前端/API/worker 镜像及 Compose，并按 `settings['channel.art.budget-reserved'].original` 恢复 AI 预算。保留艺术数据库以便恢复，不删除卷。

日后增加领域时，新增注册条目、独立配置与 API/worker 部署，再验证信源、提示词、频道隔离和预算；需要由使用者决定关注范围、分类与选题标准。

## 美妆与 CS2 结构

美妆和 CS2 各有独立分类、主题、提示词包、数据库、API、worker 与后台；共用品牌和管理员身份。结构初版信源为空、采集及模型处理关闭、预算为 0。维护者现已确认各三个信源和每频道 40 次预算，开启低频试运行，不填充虚构资讯。

美妆暂设新品、教程、测评、成分、行业、观点；CS2 暂设更新、赛事、战队、攻略、装备、社区。分类和提示词为待确认的试运行结构，正式精选仍被发布层禁止。信源与领域选题须确认后启用，并按标注样本校准门槛。

Compose 新增 beauty/cs2 的 setup、api、worker，仅内部网络互通，无新增公网端口。首次 setup 置零预算并保存持久标记，重复启动不覆盖后续后台调整。网页访问不触发模型调用。

## 已确认信源与固定预算（2026-10-07）

维护者确认：艺术采用 Colossal、Hyperallergic、Artforum News；美妆采用 Lab Muffin、Allure、Beauty Independent；CS2 采用 Valve Steam 官方更新、HLTV、Dust2.us。三个频道均为试运行，只提供摘要和原文链接，正式精选仍待标注样本校准。所有信源的正常采集间隔固定 180 分钟，关闭每日自适应频率调整；首次每个新信源最多导入 1 篇，失败走退避（可到 6 小时）。Allure 促销标题、CS2 博彩推广与外挂下载先做机械过滤，再沿用领域预筛。

艺术、美妆、CS2 的模型预算各为 1 次/分钟、6 次/滚动小时、40 次/滚动 24 小时；AI 为 7/40/380。账户另有共用硬上限 10/60/500，不因新增频道或重试而扩大。次数是请求尝试数，一篇内容可能需要多次调用，不代表文章数、金额或平台 Token 额度。

0039 增量迁移提供 model_budget_attempts 共用台账，生产启用 SHARED_MODEL_BUDGET_ENABLED。上线前暂停全部模型调用进程，把四数据库最近用量回填到 AI 库的台账，再设置 channel.account-budget 并恢复服务。每次新请求在主库账户锁下检查总额、登记本频道尝试，提交后释放锁再请求模型；已收取的回复复用不再占槽。台账保留两天。配置缺失或异常时阻止新请求，不自行放宽。原单频道和未启用共用台账的部署继续原预算逻辑。

先前临时 800 次测试的历史请求仍计入滚动窗口；若历史用量已达账户 500 上限，新调用等待窗口回落，采集可继续。各频道固定预算仍独立执行，不把其他频道剩余量自动挪用。

新加坡服务器实测：Colossal、Hyperallergic、Artforum、Allure、Valve、Dust2.us RSS 可读取；Lab Muffin、Beauty Independent、HLTV 返回 HTTP 403，保留配置，由正常退避重试，无第三方付费采集或访问限制绕过。

## 当日临时不限模型次数

维护者于 2026-10-07 授权当天不限应用模型次数。主库设置 channel.account-budget-exception.until 为当晚北京时间 00:00 的绝对时间；各次新请求都核对到期时间，过期立即恢复既有频道和账户预算，不依赖后台定时脚本。基准 40/380/500 行保持不变，所有临时请求继续记录回执与共用台账，并发限制、模型平台限制及其他付费服务预算保留。模型等待状态重新提交到正常队列处理，不伪造文章或评分。普通预算按滚动 24 小时计算，恢复后仍会计入临时期间的真实历史调用。

试点首页为任务概览，完整动态与搜索仍在 /all；搜索和分类下真正无匹配项保留无结果提示。艺术已发布资讯可通过 /art 或 /art/all 阅读；试点正式精选与日报仍待门槛校准。空日报显示发布状态与动态入口，不展示零内容报纸封面。

## 赛事、时尚与官方展览目录

CS2 新增 /cs2/events，仅列出人工核实为 Tier 1 且主办地日期仍在赛期内的赛事。当前登记 ESL Pro League S24（2026-10-03 至 10-11，Europe/Warsaw），来源为 ESL 官方赛事中心与 Pro Tour RSS。PGL 布加勒斯特尚未开赛，未加入当前跟踪；新赛事条目须核实后登记在 tracking-events.json。RSS 标题、摘要必须匹配当前赛事，其他赛季、低级别比赛和过旧报道被排除。页面展示官方阶段和原始链接，不虚构即时比分。

美妆保持六个分类键，范围扩展至时尚杂志、秀场、服饰、配饰与奢侈品牌。新增 Vogue、Harper’s Bazaar、ELLE、由巴黎世家官网链接确认的 Balenciaga 官方刊物、Hermès Finance 官方新闻。巴黎世家与爱马仕加入身份词典和主题；评分权重与门槛不变，品牌声明与独立测评区分。Hermès 主时装站返回 403，品牌新闻取公开的官方新闻门户及杂志报道，未绕过限制。

艺术新增 /art/exhibitions，接入中国国家博物馆、故宫博物院、上海博物馆官方目录。数据直接提取名称、原始展期、展厅、常设/专题/特展和暂闭标记；精确结束日期过期后自动隐藏，月末及“展期3个月”等不猜截止日。目录保留核验时间和官方详情入口。当前三馆六个目录来源，正常更新仍为 180 分钟。

0040 增量迁移提供 tracked_entries。官方目录快照在普通 collectSource 路径内写入；catalogOnly 目录不送模型评分，因此目录展示不受模型预算等待影响。公开读取仍集中在 publication/tracking.ts，受来源启用状态、editorial 参与模式、日期及核验状态约束；解析失败保留原快照，长期未更新明确标为待核验。原资讯流程、预算保护和试点正式精选限制保留。

## 任务优先界面（2026-10-09，本地版本）

`industry/channel-presentation.ts` 配置频道的首页用途和主导航顺序。艺术、美妆、CS2 首页各自优先提供看展、已有内容的主题、当前赛事；AI 原精选首页保留。桌面看展/赛事入口前移，手机底栏分别提供“概览/看展/动态/更多”“概览/动态/主题/更多”“概览/赛事/动态/更多”。空的试点日报移入更多的汇总说明；旧日报地址保留。频道切换保留可见搜索词并自动查询，搜索框明确频道范围。

看展页支持城市、馆方、类型、状态筛选与每页 12 项的分页；URL 保留筛选，优先在展与已知结束日期。`features/tracking/view-model.ts` 对旧公开快照做保守的展示修正：已识别故宫宫殿显示场馆目录，无起止日期的特展标待核验，已确认的无日期专馆重复项优先采用常设目录，官方同地址同展期的重复项采用较新核验记录。该处理不删除或更新原数据库；公开 API 和采集快照仍保留原记录，后续实体治理需要在发布读取层统一处理。

赛事卡片突出主办地当前阶段，同日决赛优先于覆盖更长日期的淘汰阶段。“赛事报道”使用本条赛事名称搜索，明确这是搜索入口；赛事 ID 与报道的强关联仍待下一批实现。日期数据不转换为虚构开赛时刻，也不提供实时比分。

此次界面改造没有新增信源、调整分类与评分门槛、改变模型预算或增加模型调用。前端仅从既有公开 API 读取。艺术首页两项看展预览与六条动态、美妆主题计数、CS2 赛事阶段均使用真实返回数据；无可用任务数据时区分无内容与暂时加载失败。
