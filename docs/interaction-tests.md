# AI Station 交互测试方案

版本：2026-10-09，任务优先多频道界面。覆盖 AI、艺术、美妆、CS2 的读者流程。

## 目标与发布标准

让读者从频道入口一直走到主题、文章、原文与收藏；操作后同时核对页面内容、URL、频道范围和选中状态。仅检查返回 200 或标题存在，不能证明整条流程可用。

- P0：详情入口断链、跨频道串数据、收藏串频道、关键入口不可用。任一失败阻止发布。
- P1：搜索/筛选/分页错误、错误状态混淆、手机导航或布局问题。涉及本次修改的 P1 必须通过。
- P2：提示文案、视觉细节与次要辅助操作。记录影响和处理计划，不以“测试通过”掩盖未检查项。
- 浏览器用例全部通过后，还需原有类型检查、构建、接口/缓存测试及上线前人工验收。固定数据测试不能证明真实信源、模型质量与持续采集正常。

## 测试环境与数据

自动测试启动真实生产构建的网页，后端替换为本机 HTTP 测试接口；不启动数据库、worker、采集或模型。使用新的随机端口作为浏览器存储范围，避免读写日常使用的收藏。所有测试接口仅绑定 `127.0.0.1`，不使用真实管理员密码、MiniMax Key 或飞书 Webhook，不转发到生产。

固定数据包括：

1. 四个频道分别具有自己的标题和摘要；文章故意使用相同 ID，验证频道隔离。
2. 所有频道都含 `SharedQuery`，旧领域分类/标签各不相同，验证保留查询与清除旧筛选。
3. 每个试点有一条主题及其完整文章详情，避免只测主题索引。
4. 上海 15 条常设展，用于 12+3 项分页；另含暂闭专馆、无日期的太和殿目录。
5. 进行中的顶级赛事含重叠淘汰阶段与决赛，验证当前阶段选择；另可切换为空赛事。
6. 空试点日报、真实缺失主题、503 接口失败和 700ms 慢响应分别模拟，避免把错误与无内容混为一谈。

测试只模拟接口返回，验证前端交互；赛事登记、展览解析、入选规则和预算逻辑继续由现有后台测试覆盖。测试目录不包含真实新闻快照与凭据。

## 自动运行

要求：Node.js 24.11+、现有 npm 依赖、已安装且可用的 ego-browser / Ego Lite。测试会自动构建；不依赖前一次的 8300 预览，也不依赖线上网站是否可访问。

当前自动执行基于 Ego Lite 的 Chromium 页面，视口覆盖 320/390/1280px；这不代表已完成 Safari、Firefox 或真实手机触摸/软键盘的兼容验证。

```bash
npm run test:interaction
```

本地预览准备给使用者查看前，另外执行：

```bash
npm run test:preview -- --base http://127.0.0.1:8300
```

这项检查直接访问实际预览的品牌、非空主题、主题页面和文章详情，可捕获“测试接口齐全，但临时预览服务漏接详情”的问题。它仅接受本机 HTTP 地址；若预览配置了公开数据回填，会产生匿名公开读取，不调用模型。若频道确实没有任何非空主题，会明确失败并要求人工核对，不能静默跳过当作通过。

结果保存在 `apps/web/test-results/interaction/`（已忽略，不进入 Git）：

- `report.md`：逐用例结果。
- `results.json`：编号、通过/失败、耗时、失败时 URL/页面内容/布局状态。
- `*-failure.txt`：失败的完整语义快照。
- `run.log`：运行日志；导入/导出的本地测试文件。
- `history/`：上次结果与失败证据的归档，避免重跑覆盖。

断言失败返回非零退出码，不把重试后的成功直接覆盖第一次失败记录。未完成浏览器验收时记录 TaskSpace ID，下次修复重跑可继续同一个空间；全部通过后关闭该测试空间。用户接管浏览器时停止，不自动绕过。

自动化优先使用可见文案、aria-label 与路由定位，禁止依靠屏幕坐标或随意选择第一个元素。关键状态等待页面内容或 URL 的实际变化，不用固定等待猜测加载完成。接口的 700ms 延迟仅用于制造慢响应。

自动测试使用“减少动态效果”媒体偏好，核对主题切换的功能与持久化，避免后台浏览空间的过渡动画拦截点击。常规动画、默认外观和肉眼观感由人工验收补充。浏览器缓存仅在当前测试 Page 暂时禁用，不清除用户的缓存、Cookie 或存储；真实缓存规则另有现有回归测试。

## 上线前人工补充

| 编号 | 级别 | 场景 | 验收要点 |
|---|---|---|---|
| MAN-01 | P0 | 线上每个频道：首页→主题→文章→原文 | 所有步骤有内容或准确空状态；真实来源链接可打开 |
| MAN-02 | P0 | 慢网换频道，中途浏览器返回，再换其他频道 | 加载/错误不会混入旧频道内容；搜索范围明确 |
| MAN-03 | P1 | 真正浏览器返回/前进、详情返回列表 | 路由与筛选恢复，合理保留列表位置，已读不跨频道 |
| MAN-04 | P1 | 手机键盘弹起、横竖屏、浏览器地址栏伸缩 | 输入/提交可用，底栏不盖住正文或按钮 |
| MAN-05 | P1 | 暗色、系统跟随、200% 字体/页面缩放 | 正文/状态/按钮清楚，无裁切；字体缩放并非仅改视口 |
| MAN-06 | P1 | 键盘 Tab 与屏幕阅读器 | 焦点可见、顺序合理、操作有名称；不只检测是否溢出 |
| MAN-07 | P1 | 收藏多标签页同步、浏览器存储不可用、配额不足 | 数据不串频道；存储失败可理解，不声称已同步云端 |

另外，新闻图片与品牌图标应做一次肉眼检查；本套自动化验证图片成功加载和结构尺寸，不能判断图片美感、授权、对比度合规或所有组件像素重叠。

## 建议执行频率

- 修改频道、导航、详情页或本地存储：36 项全跑。
- 修改采集、模型、发布逻辑：原后台回归 + 交互测试；仍使用本机模拟服务。
- 部署前：交互测试通过 + 现有 smoke 检查 + MAN-01/02/04/10。
- 增加新频道：扩充固定数据、主题详情和同 ID 收藏隔离，再接入回归；不只复制导航标题。

测试范围只验证当前已实现功能。实时比分、关注订阅与消息推送未开放，不以虚构成功步骤计入覆盖率。

## 本次发现并修正

一般列表接口故障原先也跳转到“搜索繁忙”，提示列表不受影响。现只在接口明确返回 `detail: "search busy"` 时使用搜索繁忙入口；其他 503 保留服务不可用状态。新增独立前端回归与两条浏览器断言，分别验证搜索容量与一般故障。

首轮未通过的测试日志及语义快照保留在测试结果历史中；定位错误已改为读取当前可见频道链接，避免错误地假设所有页面换频道都回首页。
